## 수정·보완 필요 — 우선순위 순

### 1. 아직 복용 시간이 오지 않은 약과 확인이 필요한 미기록을 구분할 필요

- 근거: `app/services/care_service.py`는 오늘 미완료 슬롯 중 첫 슬롯을 시각 비교 없이 `next_dose_label`로 반환한다. `CarePatient.needsAttention`과 `care_family_screen.dart`는 이 값이 있으면 빨간 확인 필요 표시를 사용한다.
- 영향: 예를 들어 아침 시간에 아직 예정 시각이 오지 않은 저녁 약도 다른 슬롯을 모두 완료했다면 확인 필요로 보일 수 있다.
- 권장: 예정/복용 시간 경과 후 완료 기록 없음/완료를 분리한다. 누락된 기록만으로 실제 미복용을 단정하지 않는다.

### 2. 일부 화면이 조회 실패를 미등록/미입력으로 표현함

- `care_manage_screen.dart`: `data == null`인 비로딩 상태에서 실제 오류도 연결된 어르신 없음으로 표시한다.
- `guardian_prescription_screen.dart`: `valueOrNull?.patients ?? []` 때문에 환자 목록 실패/로딩이 빈 선택 목록으로 보인다.
- `care_patient_screen.dart`: 일부 항목은 조회 실패 문구를 사용하지만 과거 병력·가족 병력·생활습관 등은 미입력으로 남는다. 건강정보 오류의 재시도 경로도 부족하다.
- `care_family_screen.dart`: 기존 데이터가 남아 있는 상태의 갱신 실패는 별도 실패 표시가 없어 새 데이터로 오해할 수 있다.
- 권장: 각 화면 내부에서 로딩/빈 데이터/실패/마지막 조회 기록을 구분하고 재시도를 제공한다. 제거한 전역 오프라인 배너나 상담 대상 아래 보조 문구를 다시 넣는 제안은 아니다.

### 3. 비밀번호 메뉴와 실제 기능이 일치하지 않음

- `guardian_account_screen.dart`의 비밀번호 행은 이름·휴대폰 행과 동일하게 `ProfileEditScreen(isGuardian: true)`를 연다.
- 해당 편집 화면과 `UserProfile` 저장 경로에는 비밀번호 변경 입력/전송이 없다.
- 권장: 별도의 현재/새 비밀번호 변경 기능을 구현하거나, 구현 전에는 비밀번호 행을 변경 가능한 메뉴처럼 표시하지 않는다.

### 4. 알레르기 자동 경고를 보장하는 문구가 구현보다 강함

- `care_patient_screen.dart`의 알레르기 카드에 “새 처방전을 대신 넣을 때 이 약이 들어 있으면 화면이 먼저 알려드려요”라고 표시한다.
- 처방전 등록은 DUR 결과를 사용한다. 현재 DUR의 확인 유형은 병용·연령·임부·효능군·중복성분이며, 개인 알레르기 일치 검사는 AI 약사의 건강 주의 기능에 따로 있다. 처방전 등록에서 모든 개인 알레르기를 자동 탐지한다는 근거는 확인되지 않았다.
- 권장: 자동 경고를 보장하는 문구를 수정한다. 알레르기 자동 경고 기능을 넣을 경우 공식 성분과 등록 알레르기의 확인 가능한 일치만 처리하고 확인 불가도 분명히 표시한다.

### 5. 화면 이름 변경 후 남은 오래된 안내

- 알림 기본 제목/알림 설정에 “약을 안 드셨어요/약을 안 드셨을 때”가 남아 있다. 서버 알림 본문은 완료 기록 없음으로 표현하는 경우가 있어 의미가 일치하지 않는다.
- 권장: 설정으로 경로를 통일하고, 역할별 도움말과 복약 완료 기록 기준 표현을 사용한다.

### 6. 환자 대신 상담하는데 키워드가 1인칭임

- 환자 상담의 `내 약 알려주세요`, `내 건강에서 주의할 점은요?`는 보호자 본인 이야기처럼 읽힐 수 있다. 실제 요청 대상은 환자 ID이므로 대상 전달 자체의 오류는 아니다.
- 일반 상담 예시의 아침 약/혈압약/관절약은 구체적인 제품이 선택되지 않았을 때 대상이 불명확하다.
- 권장: 등록 약/환자 건강정보 기준 표현으로 개선한다. 사용자가 유지하길 원했던 겹치는 성분 등 기존 선택별 키워드는 이번에 바꾸지 않았다.

### 7. 연결 해제가 관리 메뉴가 아니라 프로필 편집 안에 있음

- 기능이 없는 것은 아니다. `설정 → 프로필 카드 → 이름/휴대폰 등 정보 수정 → 연결된 어르신 → 연결 해제`에 실제 서버 삭제 호출과 확인 창이 있다.
- 돌보는 분 관리에서는 수락 대기 요청 취소만 바로 가능하다. 이미 연결된 환자 관리와 관계 수정 경로가 직관적이지 않다.
- 권장: 돌보는 분 관리에 연결 해제를 배치하고 관계 수정도 같은 곳에 모은다. 확인 창의 글꼴/버튼도 공통 시니어 컴포넌트에 맞춘다.

### 8. 알림 환경설정 저장 실패/다른 기기 동기화

- 알림 확인과 설정은 보호자별 기기 내 SharedPreferences에 저장된다. 다른 기기에서 확인 상태가 동일하게 유지되는 서버 동기화 기능은 아니다.
- 확인 표시는 저장 실패를 검사하지만 `GuardianAlertPrefsScreen._set`은 먼저 스위치를 바꾸고 `setBool` 반환값을 확인하지 않으며 오류 복구 안내도 없다.
- 권장: 설정 저장 실패 시 되돌리고 안내한다. 다중 기기 지원이 필요하다면 서버의 보호자별 설정/확인 정보로 이전한다.

## 후속 수정 — 사용자 요청 반영

## 제외 범위와 적용 상태

- 사용자가 제외한 오래된 심박 표시, 환자/날짜별 알림 정렬·필터, 과거 월 조회, 처방전 등록·변경 이력은 추가하지 않았다.
- 알림 확인/설정의 다른 기기 동기화는 추가하지 않고 기기 내 저장을 유지했다. DB 마이그레이션이나 새로운 푸시·문자 인프라를 만들지 않았다.
- 실제 기기 설치/카메라/Polar 실기 시험은 아직 하지 않았다. 운영 계정 변경이나 사용자 데이터 삭제는 시험하지 않았다.
- 새 복약 상태 분류는 메인 서버 수정 배포와 앱 재빌드가 필요하다. 새 앱은 구버전 서버 응답을 계속 읽을 수 있으나 구버전 서버에서는 기존 상태 판단이 유지된다.
- 아직 이번 수정의 커밋·푸시·배포는 하지 않았다.
