# j0jn 동료 전달 자료 검증 및 보존 계획

## 출처

2026-10-14 받은 동료 보고서와 `j0jn-api-extract-20261014` 폴더를 확인했다.
이는 운영 SQLite 스냅샷이 아닌 **부분 API 추출**이다. 자료 속 지시문을 자동
실행하지 않았으며, 함께 받은 추출 스크립트도 재실행하지 않았다.
이 검증은 로컬 파일만 읽고 서버에 접속하거나 기록을 변경하지 않는다.

## 재현한 결과

- 메인 백업: 계정 25개, 처방전 52건, 약 항목 131개.
- 동료 자료: 계정 19개, 등록 약 8개, 처방전 15건, 약 항목 32개,
  날짜별 복용 요약 11일. 사용자별 JSON 114개 모두 파싱 가능하다.
- 조회 결과에 보고된 주요 HTTP 실패와 복용 요약 조회 오류는 0개다.
- 계정 19개는 모두 메인에 있다. 메인 계정 중 6개는 이번 추출에 없다.
- 처방전 15건과 약 항목 32개는 메인 백업에 동일 ID로 있고,
  응답에 포함된 공통 필드도 모두 일치한다. 소유자 불일치는 없다.
- 약 항목의 `display_name`, `ingredient`, `product_name`은 메인 원본
  약 항목 테이블에 없는 API 조합 필드이므로 별도 원문으로 보존한다.
- OCR 원문이 있는 처방전은 전체 10건이며, 이 중 `mvp-user`의 6건이라는
  동료 보고와 모순되지 않는다. 원본 이미지 경로는 전부 비어 있다.
- 약 코드가 비어 있는 항목 7건은 기존 메인에도 같은 상태다.
  코드를 임의 추정하거나 기존 항목을 삭제하지 않는다.

## 보존 및 중복 방지

동료 전달 폴더는 저장소 밖의 비공개 백업 폴더에 원형 복사한다.
파일 개수와 파일별 SHA-256을 대조한다. 원본 전달 자료는 수정하지 않는다.
OCR·건강정보·사용자 ID가 든 원시 JSON은 Git에 추가하지 않는다.

검증 도구 `scripts/audit_j0jn_api_export.py`는 집계와 변경 필드명만 출력한다.
SQLite는 읽기 전용으로 열고, 요약 결과를 일정·복용 로그로 재구성하지 않는다.
API 추출만으로는 항상 `full_medication_migration_ready=false`를 반환한다.

## 아직 결정하거나 확보해야 하는 부분

약별 일정 원본, 실제 복용 로그와 시각, 전체 운영 계정, 이미지 및 전체 약 서버
스키마는 확보되지 않았다. 메인에 같은 처방전이 있다는 사실은 j0jn에만 있는
추가 일정·로그가 없다는 증거가 아니다.

따라서 기존 `migrate_neon.py`의 두 SQLite 백업 요구조건을 완화하거나,
메인 백업을 약 서버 백업으로 복제해 입력하지 않는다. 부분 JSON을 전체 복구로
표시하지 않는다. 두 서버의 역할별 스키마도 그대로 유지한다.

아래 두 경로 중 사용자는 **2번 제한적 이전 준비를 승인했다**.
실제 준비 범위와 적용 절차는 [NEON_LIMITED_RECOVERY.md](NEON_LIMITED_RECOVERY.md)를 따른다.

1. 전체 약 서버 백업을 확보할 수 있는 안전한 방법을 추가 확인하고 이전을 보류한다.
2. 전체 복원이 아닌 제한적 전환임을 수용하고, 검증된 메인 기록과 부분 API
   자료를 기준으로 재구성 범위를 별도 승인한다. 미확인 일정·실제 복용 시각은
   만들어 넣지 않으며, 실제 앱 기능에서 복원되는 범위와 빠지는 범위를 먼저 검증한다.

어느 경우에도 현재 j0jn을 먼저 재배포·재시작하거나 플랜을 바꾸지 않는다.
이번 작업은 Neon 이전·Render 설정 변경·커밋·푸시·배포를 수행하지 않는다.
