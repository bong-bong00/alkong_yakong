# 앱 전체 보완 적용과 배포 순서

## 데이터 보존

기존 계정·처방전·심박 기록을 초기화하지 않는다. 처방전 등록 표식은
`registration_revision` 열을 추가하며, 동일 처방전의 기존 ID는 유지한다.
심박 저장에는 재시도 중복을 막는 `client_request_id` 열을 추가한다.
복용 취소는 `CANCELLED` 감사 기록을 남기고 일정을 `PENDING`으로 되돌린다.

## 2026-10-14 통합 코드 계약

최신 메인 `6824519`의 두 서버 인증·보존 마이그레이션을 폴라 기능과 통합했다.
인증은 동료 구현의 2부분 HMAC 토큰으로 통일한다. 3부분 JWT인 기존 폴라
토큰과 섞어 배포하지 않으며 새 앱의 재로그인이 필요하다.
복약 완료는 `/api/v1/medication-logs/batch`, 취소는 `/api/v1/medication-logs/batch/cancel`을
사용한다. 기존 `/undo`는 같은 원자적 취소 구현으로 연결한 호환 별칭이다.
탈퇴 시 main은 `account_purge` 용도·대상 제한 서비스 토큰으로 약 서버의
`DELETE /api/v1/internal/users/{user_id}`를 먼저 확인한다. 실패 시 main 계정을 유지한다.

폴라의 AI 전문용어 설명·약 이름 요약 검증·후속 질문, 보호자 심박 기록·그래프,
가족 처방전 이력 확인, 실제 휴대폰 복약 알림 취소·미루기를 유지한다.
심박수의 기존 화면 문구(느린/정상/빠른 심박수)와 60~100 기준을 유지하며
범위 이탈 알림은 비진단적 앱 안 안내다. 수락·동의가 확인된 보호자만 수신한다.

## 두 서버의 필수 설정

영구 디스크를 사용하지 않는 Neon 이전은 [NEON_MIGRATION.md](NEON_MIGRATION.md)를 따른다.
PostgreSQL 모드에서는 SQLite 경로 대신 `NEON_DATABASE_URL`이 필요하다.
기본 모드는 SQLite로 유지하며 운영 백업/Neon 검증 전에는 모드를 바꾸지 않는다.

- 두 Render 서버에 같은 `ALKONGYAKONG_AUTH_SECRET`을 설정한다. 임의 생성한
  32자 이상의 비밀값을 Render 환경변수에만 저장하며 코드·문서·채팅에 넣지 않는다.
- 메인: `SERVICE_ROLE=main`, `MEDICATION_FEATURE_BASE_URL=https://alkong-yakong-j0jn.onrender.com`
- 약 데이터: `SERVICE_ROLE=medication`, `AUTH_AUTHORITY_BASE_URL=https://alkong-yakong.onrender.com`
- 둘 다 `AUTH_ENFORCED=true`, 실제 영구 디스크를 가리키는 `ALKONGYAKONG_DB_PATH`를 유지한다.
- 이 설정이 없으면 운영 서버는 요청을 허용하지 않는다. 보안을 끈 채 배포하지 않는다.

## 배포와 확인

1. 두 DB의 기존 백업을 확보하고 새 인증 환경변수를 준비한다.
2. 같은 수정 코드를 두 서버에 배포한다. 한쪽만 업데이트하면 권한 확인·등록·취소가 실패할 수 있다.
3. 새 Flutter 앱을 빌드·설치하고 기존 사용자도 다시 로그인한다. 옛 앱은 인증 토큰을 보내지 않는다.
   전화번호만 기록되고 보호자 계정 ID가 없던 연결은 환자의 재수락이 필요하다.
   전화번호를 입력했다는 이유만으로 기존 환자 기록을 자동 공개하지 않는다.
4. 환자/연결 수락된 보호자는 조회할 수 있고, 미연결 계정·로그인하지 않은 요청은 거부되는지 확인한다.
5. 복약 완료 → 취소 → 재조회, 동일 처방전 재등록, 보호자 복약·심박 조회를 실기 두 계정으로 확인한다.
6. 오프라인에서는 유효한 저장 세션의 자기 건강정보·이미 받아둔 약 정보만 읽을 수 있다.
   오프라인 안내를 표시하고 서버 변경 요청은 성공한 것처럼 처리하지 않는다.

## 알림 지원 범위

현재 지원 범위는 앱 안 알림과 환자 휴대폰의 로컬 복약 알림이다.
보호자 화면은 열려 있는 동안 주기적으로 조회한다. 앱 종료 상태의
보호자 푸시·문자·야간 소리 제어는 지원되지 않으며 설정 UI에서도 약속하지 않는다.
심박 60 미만·100 초과는 범위 이탈 기록을 알릴 뿐, 진단·응급 판정이 아니다.

## 테스트

Python 테스트는 임시 DB 사본에서 실행해 프로젝트 DB를 변경하지 않는다.
전체 식약처 캐시를 요구하는 테스트 2개는 실제 공식 데이터가 준비된 경우
`RUN_MFDS_DATASET_TESTS=1`로 별도 실행한다. 생략된 검사를 통과로 세지 않는다.
