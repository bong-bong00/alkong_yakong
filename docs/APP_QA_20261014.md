# 알콩약콩 실제 API·회귀 검증 기록 — 2026-10-14

## 범위와 운영 데이터 보호

`polar-dataset-v2`의 작업 중 코드로 검사했다. 운영 사용자에게 처방전·복약·심박
기록을 추가하거나 삭제하지 않았고, 서버 설정 변경·재배포·운영 DB 이전도 하지 않았다.
실제 API 검사는 메인 서버의 별도 임시 소스와 합성 사용자 SQLite에서 실행했다.
운영 DB에서 참고한 것은 백업에 있는 공개 DUR 기준 자료뿐이다.
원본 이미지와 개인정보가 들어 있는 OCR 결과는 Git에 넣지 않았다.

## 1. 약 상세 안내

- 실제 주의사항이 없을 때 약 이름별 고정 시연 부작용을 표시하던 대체 로직을 제거했다.
- 빈 주의사항을 안전하다는 뜻으로 안내하지 않고, 정보 미확인 및 전문가 확인 문구로 바꿨다.
- 기존 화면 배치·색상·버튼 구조는 유지했다.
- 서버 주의사항 우선 표시, 고정 예시 미표시, 빈 주의사항 안내를 Flutter 테스트로 확인했다.

## 2. 개인정보 안내

Gemini로 전달하는 관련 질환·과거력·알레르기·흡연·음주·최근 대화와 휴대폰의
대화/캐시 보관 내용을 안내했다. 구현되지 않은 동의 절차나 백업 자동 삭제를
이미 제공하는 것으로 설명하지 않는다.

- 운영자·문의 연락처·시행일: `PRIVACY_OPERATOR`, `PRIVACY_CONTACT`,
  `PRIVACY_EFFECTIVE_DATE` 빌드 설정으로 확정값만 지정한다. 현재 미확정이다.
- `NEON_DATABASE_ACTIVE`는 기본 false이다. **실제 두 서버 DB 전환 이후에만**
  true 빌드를 사용한다. Neon 프로젝트 생성/연결만으로 켜지 않는다.
- 기본 SQLite 안내와 Neon 활성 안내 양쪽의 문구 테스트가 통과했다.
- 별도 민감정보 동의 UI·동의 이력 저장, 운영자 정보·보유 기간·국외 처리 조건의
  확정은 남아 있다. 이번 수정은 운영 적법성 검토 완료를 의미하지 않는다.

## 3. 두 서버 인증 전환 준비

메인 Render 실행 환경을 비밀값 출력 없이 확인했다. 인증 비밀값과 역할 설정은
없었고, 인증 강제도 켜져 있지 않았다. 약 서버 주소 설정은 있었다.
현재 운영 구버전에 새 인증 코드를 한쪽만 배포해서는 안 된다.

동료 약 서버 자료 수령 후 다음 순서로 진행한다.

1. 두 운영 DB 백업과 레코드 연결 검증을 끝낸다.
2. 두 서버에 동일한 인증 비밀값을 설정하고, 메인은 `SERVICE_ROLE=main`,
   약 서버는 `SERVICE_ROLE=medication`, 양쪽은 `AUTH_ENFORCED=true`로 준비한다.
3. 메인의 `MEDICATION_FEATURE_BASE_URL`과 약 서버의 `AUTH_AUTHORITY_BASE_URL`을 확인한다.
4. PostgreSQL 전환 시 두 서버 모두 같은 Neon 주소와 해당 역할의 분리된 스키마를 사용한다.
   실제 이전 전에는 기존 SQLite 모드를 유지한다.
5. 동일 계약의 두 서버 코드와 새 앱을 함께 적용하고 재로그인한다.
6. 로그인 없는 요청 401, 다른 사용자 접근 403, 보호자 수락·동의에 따른 접근 제한,
   등록·완료·취소·탈퇴의 양쪽 서버 동작을 확인한다.

세부 절차는 `APP_HARDENING_ROLLOUT.md`와 `NEON_MIGRATION.md`를 따른다.
이번 임시 QA에서 401/403은 확인했지만, 운영 두 서버 연결 완료를 의미하지 않는다.

## 5. 실제 OCR·Gemini·식약처 호출

### 제공한 처방전 이미지

실제 CLOVA 호출 1회가 성공했다(8.26초). 114개 문자 필드와 1개 표를 반환했다.
평균 인식 신뢰도 0.93968은 업체 응답 값이며 정확도나 의료적 신뢰율이 아니다.

표 결과에 본문 행이 없고 문자 줄 순서가 섞여 두 약의 투약일수가 누락됐다.
약 이름 행과 투약량·횟수·일수 헤더의 좌표를 활용하는 보수적 대체 파서를 추가했다.
불완전한 숫자 행, 모호한 좌표·헤더, 낮은 신뢰도는 임의로 채우지 않는다.
같은 실제 응답을 수정 파서로 재처리한 결과는 다음과 같다.

| 사진의 약 | 1회 투약량 | 1일 횟수 | 투약일수 |
|---|---:|---:|---:|
| 프리마란정 | 0.50 | 3 | 7 |
| 아디팜정 | 0.50 | 3 | 7 |
| 휴온스시메티딘정200밀리그램 | 0.50 | 3 | 7 |
| 프레벨액0.25% | 1.00 | 1 | 1 |

이 사진 1장에서 이름 4/4와 복용 수치 12/12가 일치했다. 액제 투약량을 임의로
정제 개수로 해석하지 않는다. 다양한 처방전 전체에 대한 인식률을 뜻하지 않는다.
실제 의약품 등록 및 환자 계정 저장은 실행하지 않았다.
회귀 검사는 개인정보 없는 합성 좌표로 작성했다. CLOVA 오류 로그에도 제공자
오류 본문·URL을 그대로 남기지 않도록 정리했다.

### AI 약사

정확한 공식 제품명·품목기준코드로 단일 약의 사용 목적/복용법/주의사항/이상 증상,
세 약의 함께 복용/비슷한 역할/건강 주의사항, 무관한 질문 등 8개 요청을 검사했다.
합성 건강정보를 사용했다. 8개 요청 모두 HTTP 200이며 실제 Gemini 호출 12회가
응답했다. 이는 API 통신 결과이지 12개 답변의 의료적 정확도 평가가 아니다.

- 사용 목적·복용법·주의사항·이상 증상·건강 주의사항 답변에 공식 허가정보 출처가 표시됐다.
- 건강 주의사항에서 세 약의 대상 범위와 관련 건강정보 강조가 반환됐다.
- 무관한 질문은 Gemini를 호출하지 않고 의약품 질문 범위로 안내했다.
- 복용법은 공식 설명서의 일반 안내임을 고정 문구로 구분했다. 요약 후에도 유지한다.
- ‘비슷한 역할’ 질문에서 중복성분뿐 아니라 효능군중복도 요청하도록 수정했다.
  순수한 ‘같은 성분’ 질문의 기존 조회 범위는 유지한다.
- 수정 후 복용법/중복 2개 요청을 다시 실행했다. Gemini 2회 호출이 성공했고,
  복용법에 일반 안내 문구가 실제 표시됐다.

**남은 제한:** 함께 복용/중복 요청은 임시 QA 자료에서 DUR 분석을 끝내지 못했다.
앱은 이를 안전하다고 답하지 않고 검사 미완료 및 전문가 확인을 안내했다.
QA의 DUR 연결은 격리된 약 서버 코드이며 운영 j0jn과의 실제 연결 검사가 아니다.
공식 원문 대체 답변에는 전문용어가 남는 경우가 있어 쉬운 설명 품질은 추가 평가가
필요하다. 실제 환자 대상 추천이나 복용량 변경 판단은 검증하지 않았다.

## 증빙과 재현

- OCR 검사 스크립트: `scripts/qa_live_ocr_engine.py`
- 합성 사용자 실제 상담 검사: `scripts/qa_live_pharmacist.py`
- 개인 자료 포함 원시 결과는 저장소 밖의 비공개 `AlkongQA/20261014-private`에 보관한다.
- 외부 API 재실행은 비용·개인정보 전달이 수반될 수 있으므로 자동 회귀 테스트와 분리한다.
- 운영 백업의 기존 로컬 파일은 변경하지 않는다. 서버 임시 QA 파일은 수거 후 제거한다.
